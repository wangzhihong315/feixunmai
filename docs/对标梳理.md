# 对标梳理：remote-mic-app 踩过的坑 vs 我们

> 2026-10-28 基于 remote 仓库 Bugs/ 目录（343 条记录）、TROUBLESHOOTING、
> 豆包兼容说明、能力矩阵逐条对照。每条标注我们的状态与行动。

## 已对照修复（本轮落地）

| remote 踩过的坑 | 内容 | 我们的行动 |
| --- | --- | --- |
| 08-18 虚拟音频阻止 Mac 休眠 | 引擎持续运行 → coreaudiod 持有防休眠断言，Mac 永不自动休眠 | ✅ 空闲 10 分钟自动停引擎，语音到来时即时重建（0.4s 门槛缓冲覆盖冷启动）；**并撤掉我们刚引入的 `idleSystemSleepDisabled`（同款错误！）** |
| 08-17 音频通道假活 | 设备在列表里 ≠ 声音真的在流；引擎 isRunning 不等于 isPlaying/绑定有效；睡眠唤醒后通道失效需手动重选 | ✅ 睡眠唤醒通知 → 自动重建引擎；enqueue 前检查 `engine.isRunning && player.isPlaying`，假活时自动重建 |
| 07-29 音频路由变化后播放器崩溃 | 路由变化后对异常状态播放器调用 scheduleBuffer → ObjC 异常崩溃 | ✅ 已踩过（monitorPlayer 崩溃）并修复；再加 enqueue 前置守卫 |
| 08-06 HID 客户端生命周期崩溃（macOS 26+） | HID 系统客户端生命周期过短，连接遥控器时启动即崩 | ✅ 既有实现即持有 IOHIDManager；用户在 macOS 27 实测无此问题，持续观察 |

## 我们已独立踩过并修掉的（remote 也有同类）

| 我们的坑 | 对应 remote 的经验 |
| --- | --- |
| AudioSink 先连后切设备 → 静音 | 它的 AudioOutput 顺序（连 player→mixer、先选设备再 start）+ 虚拟设备可听性修复 |
| 语音键 F5 回声干扰语音工具 | KeyboardEventSuppressor 的"布防-拦截"架构（已移植）+ 合成模式吞 F5 |
| 配置外部写入与运行实例互相覆盖 | 它的设计是设置只存 App 内；我们已定纪律：UI 是唯一写入方 |
| 真键盘回车/方向键被误拦 | 布防窗口架构（同它的 suppressor），真键盘永远直通 |

## 对照后确认的差距（待办，按优先级）

| 项 | remote 的经验 | 我们的行动 |
| --- | --- | --- |
| ~~**豆包识别不了虚拟麦**~~ | 自建 MiRemoteV 2ch（BlackHole 0.7.1 改名+USB transport）专供豆包 | ✅ **已完成（2026-10-28）**：同方案自编译 **FeiXunV 2ch**（BlackHole 0.7.1 源码，设备 transport 改报 USB、独立 BundleID `com.feixun.driver2ch`），豆包实测自动识别；驱动已进安装包，GPL 许可证与源码随仓库（driver/BlackHole-0.7.1）|
| **HID 报告偶发丢失无法定位** | OK 键偶发无响应：旧日志只在成功后记录，丢在哪层无从判断 → 每层都写日志 | 待办：做 HID 系统性验证时（计划已列），每层（回调/布防/解析/动作）加可开关日志 |
| **按键重复触发/系统提示音** | 排障指南专章：按住连发与系统提示音的冲突处理 | 我们的删除键自驱动连删已避开系统重复；验证计划里专项测 |
| **UI 卡片排序要符合实体位置** | 主页/音量键卡片放错列被用户指出连线交叉 | 待办：映射列表行序改成实体布局序（OTT→OK→菜单/返回→主页）|
| **多遥控器 HID 路由** | 两只遥控器按指纹路由 | 我们单设备按 VID/PID 匹配；用户若接两只斐讯遥控器需注意（暂不做） |
| **触发键与工具模式错配** | 能力矩阵：长按型 vs 按一次型，配错就"点一下结束没生效" | 已覆盖：点按切换开关 + Fn/⌘/⌥ 合成模式；UI 已写明适配关系 |

## 结论

- 架构层面（事件布防、音频接线、触发门槛、配置纪律）已与 remote 对齐；
- **休眠与音频假活两类是隐藏最深的坑**，remote 用了专门的 bug 记录才定位，本轮已提前堵上；
- 剩余最大差距是**豆包专属驱动**（决定豆包能否免手动选麦克风），这是下一个大件。
