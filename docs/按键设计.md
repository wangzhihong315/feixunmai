# 按键设计（对标 OpenAI Codex Micro）

> 状态：**2026-10-28 语音链路端到端验收通过**（用户以豆包语音输入实测出字）。
> 实验数据见《遥控器能力摸底.md》。

## 系统架构定稿（2026-10-28）

```
遥控器语音键 ─┬─ GATT 07fc01/07fc07 + mSBC 音频流 → 解码 → 0.4s 门槛 → 缓冲排空
              └─ HID 回声 F5(96)：合成模式下被布防吞掉（防误触发其他语音工具）

门槛通过 ──┬─ 合成 Fn 长按（默认；豆包/微信输入法出厂快捷键）
           ├─ 期间系统默认输入自动切 BlackHole，松开还原真麦（键盘语音不受影响）
           ├─ 缓冲的音频 + 实时音频 → BlackHole（供语音应用收音）
           └─ 会话结束 → 统计 +1
```

关键配置（UI 为唯一合法写入方；外部 defaults 只能在应用停止时改）：
- 语音键模拟：Fn 长按（合成，默认）/ 原生 F5（仅限快捷键=F5 的工具，如微信输入法）/ ⌘/⌥ / 不发送
- 点按切换：给"按一下开始"式工具（豆包免按模式等）
- 语音时自动切换系统麦克风：默认开
- 说话时本机同时出声（双路输出）：默认关
- 诊断日志：`defaults write com.feixun.mai debugDiag -bool YES`（应用停止时改）

### 已知坑与对策（全部实测踩过）

| 坑 | 对策 |
| --- | --- |
| AudioSink 先连 mixer→output 再切设备 → 静音 | 只连 player→mixer，先选设备再 start（对齐 remote AudioOutput） |
| 系统设置输入电平表不渲染虚拟设备 | 用 QuickTime 电平表验证；ffmpeg 无麦克风权限录到的全是假静音 |
| 监听引擎关闭时 enqueue 喂它 → 崩溃 | monitorActive 状态位守卫 |
| 外部 defaults write 与运行中应用互相覆盖 | 配置只从 UI 改；外部改动先 pkill |
| 豆包"自动检测"识别不了虚拟麦（豆包自身问题） | 豆包设置里手动选 BlackHole 2ch；长期方案=编译改名驱动（对齐 MiRemoteV 2ch） |

## 对标分析

Codex Micro（OpenAI × Work Louder，约 $230）默认能力：
6 个命令键（接受改动 / 拒绝输出 / **按住说话 PTT** / 新会话 / 自定义动作等）、
**摇杆**（导航）、旋钮（切换会话），全部可重映射，RGB 显示 agent 状态。

我们的硬件（斐讯遥控器 13 键）与它的对应关系：

| Codex Micro | 我们 | 说明 |
| --- | --- | --- |
| 摇杆（导航） | 上/下/左/右 | 开「方向键当鼠标」后 = 鼠标移动，按住加速 |
| 摇杆下压（确认） | **OK** | **→ 鼠标左键**（按住=按下可拖动，松开=抬起） |
| Push-to-talk | 语音键 | 长按说话，音频流触发，已实现 |
| 命令键（接受/拒绝/新会话…） | 主页/返回/菜单/OTT电源 | 可映射：回车/Esc/复制/粘贴/左键等 |
| 旋钮（音量类） | 音量 +/− | 保持系统音量（遥控器硬件音量直通） |
| RGB 状态灯 | （无硬件） | 菜单栏图标颜色/统计页代替，低优先级 |

## 设计原则（从 Codex Micro 学的）

1. **极少数高频动作做到零学习成本**：移动、点击、说话，三个动作覆盖 90% 场景；
2. 命令键默认给"系统级安全动作"，面向 AI 编辑器的高频组合键（如接受/拒绝）
   由用户自己映射——不同编辑器快捷键不同，应用不替用户猜；
3. 一切可重映射，但**默认即好用**（不开设置也能用）。

## v1 默认方案（2026-10-28 定稿，广谱场景，不绑定 Codex）

设计立场：不抄 Codex Micro 的"接受/拒绝"（那是它绑定 Codex 的场景），
按 macOS 通用遥控器来定。固定角色：**语音键=PTT、方向键+OK=鼠标、音量±=系统音量**。
四个命令键按"语义最近"给默认值，全部可重映射：

| 按键 | 默认动作 | 理由 | 实现状态 |
| --- | --- | --- | --- |
| 上/下/左/右 | 鼠标移动（按住加速） | 摇杆 | ✅ |
| OK | 鼠标左键（鼠标模式开启时；关闭时=回车直通） | 摇杆下压=确认 | ✅ |
| 语音键 | **原生 F5 直连（推荐，零注入）**：语音键硬件原生发 F5 (kc=96)，把它直接作为语音应用的触发键；合成注入（Fn/⌘/⌥）降级为兼容备选 | 对齐 remote 的 Fn 硬件模式（usesHardwareMapping），无权限需求、无合成兼容性问题；2026-10-28 实测端到端出字（微信输入法 "1234123412341234"） | ✅ |
| 返回 | **删除（退格，按住连删）** | 位置顺手（挨着语音键），删除高频；按住连删自己驱动 | ✅ |
| 菜单 | **回车（发送）** | 语音出字→回车发送是最高频动作 | ✅ |
| 主页 | **Esc** | 底部边缘不好按，放低频的取消动作 | ✅ |
| OTT电源 | **粘贴 ⌘V** | 输入场景高频（用户反馈撤下右键/锁屏默认） | ✅ |
| 音量 +/− | 系统音量 | 硬件直通 | 固定 |

备选动作（UI 里随时改）：回车 / Esc / 删除 / 复制 ⌘C / 粘贴 ⌘V / 左键 /
右键 / 调度中心 / 锁屏 / 屏蔽。

> 2026-10-28 用户反馈：右键和锁屏没必要，输入要有删除键 —— 已按此调整默认值，
> 右键/锁屏保留在备选列表里。

面向 AI 编辑器的高频组合键（如 Cursor 的 ⌘K、接受改动 ⌘⏎）不设默认，
等实际使用后由用户映射到主页/菜单/OTT电源（这三键改绑后原默认动作可挪到别的键）。

## 拦截架构：布防-拦截（2026-10-28 重构，关键教训）

**问题**：遥控器 OK = mac 键码 36 = 真键盘回车；方向键 123–126 = 真键盘方向键。
早期实现按"键码匹配"拦截，导致真键盘回车被禁用、方向键被当成鼠标。

**方案**（照抄 remote-mic-app `KeyboardEventSuppressor` 的 arm-then-suppress）：

1. `ButtonMonitor`（IOHIDManager，只匹配遥控器 VID 0x005D/PID 0x0001）收到
   HID 报告 = 按键确证来自遥控器 → 给对应 mac 键码/消费 usage **布防 2 秒**
   （松开报告再补 0.3 秒窗口覆盖 keyUp）；
2. `KeyInterceptor`（CGEventTap）**只吞布防窗口内**的事件并执行映射动作；
3. 未布防的按键（真键盘的一切）原样直通；
4. 音量键不布防（保持系统直通）；语音键 F5 回声（kc=96）只布防不动作（纯吞）；
5. OTT 电源（HID 0x66）无标准 mac 键码，在 HID 层直接触发映射动作。

⇒ 真键盘回车/方向键与遥控器互不干扰（2026-10-28 用户验收通过）。
已知取舍：遥控器按住 OK 的 2 秒布防窗口内，真键盘回车也会被吞——概率极低，暂接受。

## 备注

- OK 保留"回车"能力：不开「方向键当鼠标」时 OK 仍是回车；开了以后用
  按键映射把 OK 设回「回车」即可换回来。
- 左键点击发生在**当前光标位置**；先按 OK（按下），方向键移动 = 拖动，
  松开 OK = 完成拖放 —— 这组组合是"遥控器操作电脑"的完整闭环。
- Codex Micro 的"接受/拒绝"没有做成默认键：Cursor/Zed/Xcode 的快捷键各不相同，
  等用户实际使用后把高频组合键映射到主页/菜单/OTT电源。
